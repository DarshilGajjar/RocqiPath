# RocqiPath Studio implementation plan

**Goal:** Deliver the approved local pathology workspace backed by RocqiPath.
**Spec:** `docs/superpowers/specs/2026-09-07-studio-design.md`.
**Architecture:** Static React UI served by a loopback FastAPI service; SQLite
metadata and one subprocess worker; existing RocqiPath APIs remain unchanged.
**Constraints:** Python 3.10–3.11; local only; preserve public library imports;
read original slides without modifying them; isolate generated outputs per job.

- [ ] Backend: implement `studio/server.py`, `store.py`, `slides.py`,
  `workflows.py`, `worker.py`, `__main__.py`. Tests in `tests/test_studio.py`
  begin with `client.post('/api/folders', json={'path': str(tmp_path)})`, then
  assert discovered slide metadata, tile bytes and traversal rejection. Queue a
  cell-count job on a generated TIFF and assert persisted completion/artifacts.
  Failure and cancellation must be distinguishable. Run tests before and after.
- [ ] Interface: scaffold `studio-web`; implement `app/page.tsx` and styles.
  Build library and viewer first, open a meaningful local preview, then connect
  folder browser, five workflow forms, job history, logs and downloads.
- [ ] Delivery: package static output under `studio/static`; add `studio` extra
  and launcher command. Document installation and local start. Run existing and
  new tests, frontend production build and HTTP smoke checks; review final diff.

Execution ruling: the user approved the complete design and local implementation;
proceed through the plan without additional scope-approval pauses. Implement in
this checkout on a feature branch; use independent review after integration.
